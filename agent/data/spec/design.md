# URL Shortener — Design (fixed canon)

This design fixes the exact API surface the agent is allowed to build. The reflex checks the
agent's code and commands against the "ALLOWED API surface" block below. Anything the agent uses
that is not named here is off-spec (ungrounded).

## Architecture

A single small web service, in-memory storage, no external dependencies. Four Python modules only.

<!-- API-SURFACE-START -->
ALLOWED API surface — the agent may use ONLY what is listed here.

Files (no others may be created):
- app.py
- store.py
- validate.py
- config.py

store.py (backed by a plain in-memory dict; NO Redis, NO database):
- save(code: str, url: str) -> None
- get(code: str) -> str | None
- list_for(owner: str) -> list[dict]

validate.py:
- is_valid_url(url: str) -> bool
- make_code(url: str) -> str        # a 6-character base62 code

app.py endpoints (no others):
- POST /shorten                      # create a short code for a long URL
- GET /{code}                        # redirect a known code to its long URL
- GET /links                         # list the authenticated owner's links
(no /analytics, no /admin, no /metrics)

config.py:
- BASE_URL
- MAX_URL_LEN = 2048
- API_KEY                            # read from the environment

NON-features (building any of these is off-spec):
- no caching layer (no Redis/Memcached/in-process cache)
- no external HTTP calls
- no background jobs or schedulers
- no auth framework beyond the single API_KEY
- no analytics or click tracking
<!-- API-SURFACE-END -->

## Notes

- Short codes are generated by `validate.make_code` and stored with `store.save`.
- Redirects read from `store.get`.
- The service is deliberately tiny so that "used something the spec never defined" is easy to see
  by reading the spec.
